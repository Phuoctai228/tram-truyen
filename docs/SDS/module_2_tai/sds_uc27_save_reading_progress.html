9. Save Reading Progress (UC-27)

b. Class Specifications

BookshelfController Class

No Method Description
01 completeChapter - Input: payload: Map<String, Integer>, authentication: Authentication.
- Output: ResponseEntity<?>.
- Internal Method Processing: Handles POST /api/user/reading/complete-chapter AJAX request triggered when the reader reaches the chapter completion threshold. Verifies user authentication; if unauthenticated, returns HTTP 401. Extracts chapterId from the JSON request body (returning HTTP 400 if missing), calls bookshelfService.recordChapterRead(email, chapterId), and returns HTTP 200 with {"status": "recorded"}.

BookshelfService Interface

No Method Description
01 recordChapterRead - Input: email: String, chapterId: Integer.
- Output: void.
- Internal Method Processing: Records or updates the user's chapter reading completion state and timestamp.
02 isChapterRead - Input: email: String, chapterId: Integer.
- Output: boolean.
- Internal Method Processing: Checks whether the user has already marked the specified chapter as read.

BookshelfServiceImpl Class

No Method Description
01 recordChapterRead - Input: email: String, chapterId: Integer.
- Output: void.
- Internal Method Processing: Resolves the User via getUserByEmail(email) and fetches the Chapter via chapterRepository.findById(chapterId) (throwing ResourceNotFoundException if not found). Looks up an existing UserChapterActivity via userChapterActivityRepository.findByUserAndChapter(user, chapter) or instantiates a new record, sets isRead = true and readAt = LocalDateTime.now(), and saves the record via userChapterActivityRepository.save(activity).
02 isChapterRead - Input: email: String, chapterId: Integer.
- Output: boolean.
- Internal Method Processing: Queries userChapterActivityRepository.findByUserAndChapter(user, chapter) and returns true if isRead is enabled on the activity record.
03 getUserByEmail - Input: email: String.
- Output: User.
- Internal Method Processing: Queries userRepository.findByEmail(email) and returns the authenticated User entity or throws ResourceNotFoundException.

UserChapterActivityRepository Interface

No Method Description
01 findByUserAndChapter - Input: user: User, chapter: Chapter.
- Output: Optional<UserChapterActivity>.
- Internal Method Processing: Finds an existing user-chapter activity entry by user and chapter references.
02 save - Input: activity: UserChapterActivity.
- Output: UserChapterActivity.
- Internal Method Processing: Inserts a new activity record or updates the existing record with is_read = TRUE and the latest read_at timestamp.

ChapterRepository Interface

No Method Description
01 findById - Input: id: Integer.
- Output: Optional<Chapter>.
- Internal Method Processing: Retrieves a chapter entity by its primary key ID.

UserRepository Interface

No Method Description
01 findByEmail - Input: email: String.
- Output: Optional<User>.
- Internal Method Processing: Retrieves the user entity by email address.

d. Database Queries

1. Retrieve authenticated user by email

SELECT id, email, full_name, status FROM users WHERE email = ?;

2. Retrieve chapter by primary key ID

SELECT id, novel_id, chapter_number, title, status, is_deleted FROM chapters WHERE id = ?;

3. Check existing reading/unlock activity for user and chapter

SELECT id, user_id, chapter_id, is_read, read_at, is_unlocked, price_paid, unlocked_at FROM user_chapter_activities WHERE user_id = ? AND chapter_id = ?;

4. Upsert reading completion status and timestamp

INSERT INTO user_chapter_activities (user_id, chapter_id, is_read, read_at) VALUES (?, ?, TRUE, CURRENT_TIMESTAMP) ON CONFLICT (user_id, chapter_id) DO UPDATE SET is_read = TRUE, read_at = CURRENT_TIMESTAMP;
