1. Assumptions & Dependencies

[Record any assumptions that were made when conceiving the project and writing this vision and scope document. Note any major dependencies the project must rely upon for success, such as specific technologies, third-party vendors, development partners, or other business relationships.]

AS-1: Users (Guest, Member, Staff, Admin) have a stable internet connection and use modern web browsers to access the system.
AS-2: The Staff and Admin team will be responsible for moderating copyright and the quality of novel content before publishing it on the platform.
DE-1: The system depends on third-party payment gateways (VNPay, Momo Sandbox) to process users' Coin top-up transactions.
DE-2: Google OAuth2 integration is required to support the quick Social Login feature for users.
DE-3: The project relies on Cloudinary for storing and delivering image assets (novel covers, user avatars).
DE-4: The system requires a Mail Server service (e.g., Gmail SMTP) to handle sending emails containing OTP codes for account verification and password reset.

2. Limitations & Exclusions

[Identify any product features or characteristics that a stakeholder might anticipate, but which are not planned to be included in the new product]

LE-1: Mobile Application: The system is solely a Web-based platform (using Spring MVC and Thymeleaf). Dedicated mobile applications (iOS/Android Mobile Apps) are not within the development scope of this project.
LE-2: Withdraw/Refund: Coins topped up into the system by users can only be used to unlock VIP chapters and cannot be converted back to cash, withdrawn, or refunded under any circumstances.
LE-3: User-generated content: Regular members do not have the right to create and upload their own novels. Adding and publishing content is entirely managed by Staff/Admin.
LE-4: Comic/Manga support: Trạm Truyện currently only supports purely text-based novel formats and does not support image-based comic/manga formats.
LE-5: SPA Architecture: In the main version, the system's Frontend does not adopt the SPA (Single Page Application) architecture or fully separate REST APIs, but instead uses a Server-side Rendering mechanism.
LE-6: Audio Reader quality: The voice reading feature (Audio Reader) depends on the default Text-to-Speech Engine of the user's browser/operating system, thus the voice quality may vary across different devices.
