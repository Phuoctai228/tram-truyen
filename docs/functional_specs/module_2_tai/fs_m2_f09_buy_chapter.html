M2-F09. Buy Chapter

Function Trigger: A logged-in Member attempts to read a locked VIP chapter and clicks the "Unlock with Coin" button on the prompt overlay.

Function Description: Facilitates the unlocking of premium (VIP) content by deducting the specified amount of Coin from the user's wallet. Ensures secure concurrent transaction handling so that users do not spend Coin multiple times for the same chapter.

Function Details

  • Preconditions
    • The user must be logged in as a Member.
    • The chapter must be published and marked as VIP.
    • The user must have a Coin balance greater than or equal to the chapter's price.
  • Process
    • Initiate Transaction:
      • The system receives the unlock request for a specific chapter ID.
    • Concurrency and Verification Check:
      • The system acquires a lock or uses optimistic locking on the user's wallet to prevent concurrent race conditions.
      • The system verifies the user has not already unlocked this chapter.
      • The system checks if the user's current Coin balance is sufficient.
    • Deduct Balance and Record:
      • The system deducts the specified Coin amount from the user's wallet.
      • The system creates a transaction record representing the usage of Coin for this specific chapter.
      • The system creates an unlock record granting the user permanent reading access to the chapter.
    • Provide Access:
      • The system automatically reloads or fetches the chapter's full text content and displays it to the user.
  • Alternative Flow (Insufficient Balance)
    • If the user does not have enough Coin:
      • The system halts the transaction.
      • The system displays an "Insufficient Balance" message and provides a button linking to the Top-up Coin (M3-F11) page.
  • Postconditions
    • The user's Coin balance is reduced, and they gain permanent access to read the VIP chapter.
  • Error Handling
    • Concurrency/Timeout Error: If the transaction cannot be safely completed due to server load or lock contention, the system aborts the process, does not deduct any Coin, and asks the user to try again.
  • Security Measures
    • Transactions must be processed within an ACID-compliant database transaction block to prevent data corruption or double-spending.
