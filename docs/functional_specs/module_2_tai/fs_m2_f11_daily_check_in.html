M2-F11. Daily Check-in

Function Trigger: A logged-in Member clicks the "Check-in" or "Claim Reward" button on the homepage or their profile dashboard.

Function Description: Encourages daily user engagement by allowing members to check in once per day to receive a small reward of free Coin, which can be accumulated to unlock VIP chapters.

Screen Layout:
[Placeholder for UI mockups: Check-in widget showing streak and reward amount]

Function Details

  • Preconditions
    • The user must be logged in as a Member.
    • The user must not have already checked in on the current calendar day (server time).
  • Process
    • Validate Eligibility:
      • The system checks the latest check-in record for the user to confirm it does not fall within the current day.
    • Process Reward:
      • The system calculates the reward amount (a fixed value or a variable amount based on consecutive login streaks).
      • The system adds the calculated Coin amount to the user's wallet.
      • The system creates a transaction record indicating a system-generated Coin deposit.
      • The system records the current timestamp as the user's latest check-in time.
    • Interface Update:
      • The system displays a celebratory notification showing the amount of Coin received.
      • The system updates the Check-in button to a disabled or "Claimed" state.
  • Alternative Flow (Already Checked In)
    • If the user attempts to check in again on the same day (e.g., via direct API call or concurrent clicking):
      • The system rejects the action, does not award Coin, and displays a message indicating they have already claimed their reward for today.
  • Postconditions
    • The user's Coin balance increases, and their daily check-in streak is updated.
  • Error Handling
    • Concurrency Handling: If two requests are sent simultaneously, optimistic locking on the user's record ensures only the first request succeeds and awards Coin.
  • Security Measures
    • The check-in validation relies strictly on secure backend server time, preventing users from manipulating client-side clocks to claim multiple rewards.
