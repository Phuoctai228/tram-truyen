UC ID and Name: UC-09 Buy Chapter
Created By: Tài Date Created: 2026-09-18
Primary Actor: Member Secondary Actors: None
Trigger: Member clicks the "Unlock for X Coin" button on a locked VIP chapter overlay.
Description: Handles the transaction logic for purchasing permanent access to a VIP chapter using the member's Coin balance. Uses strict database locking to prevent race conditions and double-spending.
Preconditions:

PRE-1. The chapter must be marked as PUBLISHED_VIP.

PRE-2. The user must be logged in as a Member.
Postconditions:

POST-1. Coin balance is deducted and the chapter is permanently unlocked for the member.
Normal Flow:

A. Buy Chapter Successfully

  1. Member clicks "Unlock" on a VIP chapter.
  2. The system initiates a database transaction with a pessimistic write lock on the user's wallet record.
  3. The system retrieves the current Coin balance of the member.
  4. The system determines the Coin balance is greater than or equal to the chapter price.
  5. The system deducts the chapter price from the member's wallet.
  6. The system creates a new transaction log entry mapping the purchase to the chapter.
  7. The system creates an unlock record granting the member permanent access to the chapter.
  8. The system commits the transaction and releases the lock.
  9. The system refreshes the page and renders the unlocked reading interface (continuing to UC-03).
Alternative Flows:

A.4 Alt Insufficient Balance

  1. The system determines the member's Coin balance is lower than the chapter price.
  2. The system rolls back the transaction (releasing the lock).
  3. The system displays an error message: "Insufficient Coin balance."
  4. The system renders a "Top-up Now" button linking to the payment page.
  5. Back to step 1.
Exceptions:

EX-2 Concurrency Error

  1. The system encounters a database timeout while attempting to acquire a lock (e.g., due to rapid simultaneous clicks).
  2. The system rolls back any pending changes.
  3. The system displays a "System busy, please try again" message.
Priority: Critical, Must Have
Frequency of Use: High
Business Rules: BR-20, BR-21
Other Information: None
Assumptions:
  • Member has a stable internet connection.
