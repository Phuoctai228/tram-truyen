UC ID and Name: UC-11 Daily Check-in
Created By: Tài Date Created: 2026-09-18
Primary Actor: Member Secondary Actors: None
Trigger: Member clicks the "Check-in" button on the homepage or user profile.
Description: Allows a member to claim a daily reward (free Coin) once every server-day to encourage user retention. The system uses optimistic locking to ensure the reward is only claimed once per day.
Preconditions:

PRE-1. The user must be authenticated as a Member.
Postconditions:

POST-1. Free Coin is added to the member's wallet and the check-in time is recorded.
Normal Flow:

A. Check-in Successfully

  1. Member clicks the "Check-in" button.
  2. The system initiates a database transaction for the member's wallet record.
  3. The system retrieves the `last_checkin_time` field.
  4. The system determines the current server date is strictly greater than the date of `last_checkin_time`.
  5. The system calculates the free Coin reward amount based on the current consecutive check-in streak.
  6. The system adds the reward to the member's Coin balance.
  7. The system updates the `last_checkin_time` to the current timestamp.
  8. The system commits the transaction to persist the update.
  9. The system displays a success modal showing the amount of Coin received.
Alternative Flows:

A.4 Alt Already Checked In

  1. The system determines the current server date is identical to the date of `last_checkin_time`.
  2. The system aborts the transaction.
  3. The system displays an error message indicating the member has already checked in today.
  4. Back to step 1.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system determines the actor is not logged in.
  2. The system displays an authentication error message.
  3. The system redirects the user to the login page.

EX-2 Optimistic Lock Failure

  1. The system encounters a version mismatch when committing the transaction (e.g., due to double-clicking).
  2. The system rolls back the transaction.
  3. The system displays a generic "System busy" message.
Priority: Medium, Should Have
Frequency of Use: High (Once per day per user)
Business Rules: BR-22
Other Information: None
Assumptions:
  • Member has a stable internet connection.
