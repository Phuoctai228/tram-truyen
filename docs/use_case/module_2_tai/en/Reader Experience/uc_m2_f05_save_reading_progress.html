UC ID and Name: UC-27-Save Reading Progress
Created By: TaiTP Date Created: 2026-09-18
Primary Actor: Member Secondary Actors: None
Trigger: Member scrolls through an unlocked or free chapter on the reading page and reaches at least 95% of the chapter content, or views a short chapter whose content fully fits within the viewport.
Description: Allows the system to automatically save the Member's scroll position locally in browser localStorage and asynchronously record chapter completion (isRead = true and readAt timestamp) on the server when the Member scrolls to at least 95% of the chapter or when short chapter content fully displays within the visible viewport.
Preconditions:

PRE-1. Member is authenticated and actively reading an unlocked or free chapter.
Postconditions:

POST-1. The Member's chapter activity record is marked as read with the latest timestamp in the database, updating both Reading History and Bookshelf completion progress.
Normal Flow:

A. Save Reading Progress Automatically

  1. Member scrolls through the chapter content on the reading page.
  2. The client script updates the top reading progress bar and saves the current scroll percentage and last-read chapter metadata to browser localStorage.
  3. When the scroll progress reaches at least 95%, the client script dispatches an asynchronous request containing the chapter ID to the server.
  4. The system validates the Member's session and retrieves the target chapter.
  5. The system creates or updates the Member's chapter activity record, setting the read flag to true and updating the read timestamp to the current time.
  6. The system returns a success status to the client silently without interrupting the reading experience.
Alternative Flows:

A.1 Restore Saved Scroll Position on Return

  1. Member re-opens a chapter that has a saved scroll percentage between 3% and 95% in browser localStorage.
  2. The system automatically scrolls the viewport to the saved position and displays a toast notification indicating the reading position was restored.
  3. Back to step 1.

A.2 Short Chapter Auto-Completion

  1. Member opens a chapter with short content that completely fits within the viewport without scrolling.
  2. The client script detects that the bottom of the content is within the visible viewport, updates the progress bar to 100%, and triggers an asynchronous completion request to the server.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system detects an unauthenticated request when recording server-side chapter completion.
  2. The system returns an unauthorized response and the client keeps progress locally in browser localStorage without interrupting the reader.

EX-2 Short Chapter Non-Scrollable Exception

  1. The chapter content is short or the remaining scroll distance is negligible (≤ 80px due to bottom padding).
  2. The client script automatically recognizes the short chapter, displays 100% progress, and dispatches the completion request after page load or upon clicking the next chapter button ("Chương sau").

EX-5 Silent Sync Failure

  1. The asynchronous server update fails due to a network drop or server error.
  2. The client catches the error silently so the Member's reading experience is not disrupted.
Priority: Medium, Should Have
Frequency of Use: Very High
Business Rules: BR-13, BR-14
Other Information: Completion trigger fires once per chapter page load when scroll percentage reaches at least 95%.
Assumptions:
  • Member has stable internet connection.
