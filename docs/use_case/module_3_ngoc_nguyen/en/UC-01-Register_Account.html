Functional Description Template

UC ID and Name: UC-01-Register Account
Created By: Ngoc Nguyen Date Created: 2026-09-19
Primary Actor: Guest Secondary Actors: None
Trigger: Guest accesses the registration page.
Description: Guest creates a new account in the system using their email and password.
Preconditions:

PRE-1. Guest must not be logged into the system.
Postconditions:

POST-1. A new account is created with PENDING_VERIFICATION status.

POST-2. An OTP verification email is sent to the provided email address.
Normal Flow:

A. Register Account Successfully

  1. Guest accesses the registration page.
  2. The system displays the registration form.
  3. Guest enters email, password, and confirm password.
  4. Guest clicks the "Đăng ký" button.
  5. The system validates the input data formats.
  6. The system verifies that the email does not exist in the database.
  7. The system hashes the password.
  8. The system creates a new user account with pending status.
  9. The system generates an OTP code.
  10. The system sends the OTP code to the Guest's email address.
  11. The system displays a success message.
  12. The system redirects Guest to the OTP verification page.
Alternative Flows:

A.5.1 Alt Invalid Input Format

  1. The system detects invalid email format or password does not meet requirements.
  2. The system displays a validation error message.
  3. Back to step 3.

A.5.2 Alt Passwords Do Not Match

  1. The system detects that the password and confirm password do not match.
  2. The system displays a validation error message.
  3. Back to step 3.

A.6.1 Alt Email Already Exists

  1. The system detects that the email is already registered.
  2. The system displays an error message indicating the email is in use.
  3. Back to step 3.
Exceptions:

EX-8 Database Connection Failure

  1. The system fails to save the account due to a database error.
  2. The system displays a system error message.
  3. Back to step 1.

EX-10 Email Sending Failure

  1. The system fails to send the OTP email.
  2. The system displays an error message.
  3. Back to step 1.
Priority: High
Frequency of Use: High
Business Rules:
  • Password must be hashed using BCrypt.
Other Information: None
Assumptions:
  • Guest has stable internet connection.
