UC ID and Name: UC-01 Register Account
Created By: Nguyễn Ngọc Date Created: 2026-09-19
Primary Actor: Guest Secondary Actors: None
Trigger: Actor clicks the "Register" button on the navigation bar or login modal.
Description: Allows a guest to create a new account using an email and password. Passwords are encrypted using BCrypt, and the account is created with a pending status until email verification is complete.
Preconditions:

PRE-1. The guest is not currently logged into any account.

PRE-2. The system's email service is fully operational.
Postconditions:

POST-1. A new user record is created in the database with a status of PENDING_VERIFICATION.
Normal Flow:

A. Register Account Successfully

  1. Actor clicks the "Register" button.
  2. The system renders the registration form, requesting Email, Username, Password, and Confirm Password.
  3. Actor enters the required information and submits the form.
  4. The system validates the form inputs (e.g., password strength, matching passwords).
  5. The system queries the database to ensure the provided email is not already registered.
  6. The system queries the database to ensure the provided username is not already taken.
  7. The system hashes the password using the BCrypt algorithm.
  8. The system creates a new user record with USER_STATUS set to PENDING_VERIFICATION and assigns the default ROLE_MEMBER.
  9. The system triggers an asynchronous task to send an OTP verification email to the provided address.
  10. The system displays a success message instructing the actor to check their email.
  11. The system redirects the actor to the Account Verification page (UC-02).
Alternative Flows:

A.4 Alt Invalid Form Data

  1. The system determines one or more fields are invalid (e.g., passwords do not match, weak password).
  2. The system renders specific validation error messages below the respective fields.
  3. Back to step 3.

A.5 Alt Email Already Exists

  1. The system determines the email is already associated with an existing account.
  2. The system displays an error message: "Email is already in use."
  3. Back to step 3.
Exceptions:

EX-9 Email Service Failure

  1. The asynchronous task fails to send the email (e.g., SMTP server timeout).
  2. The system logs the failure.
  3. The system allows the user record to remain pending, but the user will need to manually request a new OTP via the verification page.
Priority: Critical, Must Have
Frequency of Use: High
Business Rules:
  • Passwords must be hashed using BCrypt before persisting to the database. Plain text passwords must never be logged or stored.
  • The system must enforce strong password policies (e.g., minimum 8 characters).
Other Information: None
Assumptions:
  • Actor has a valid email address and stable internet connection.
