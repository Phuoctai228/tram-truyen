Functional Description Template

UC ID and Name: UC-11 Top-up Coin
Created By: Nguyễn Ngọc Date Created: 2026-09-19
Primary Actor: Member Secondary Actors: VNPay Gateway
Trigger: Actor selects a Coin package on the "Top-up" page and clicks "Pay with VNPay".
Description: Handles the entire payment flow for adding Coins to the member's wallet, integrating with the VNPay Sandbox environment. Includes secure request generation (HMAC-SHA512) and asynchronous IPN callback handling.
Preconditions:

PRE-1. The actor is currently authenticated as a Member.

PRE-2. VNPay Sandbox credentials (TmnCode, HashSecret) are configured in the system environment.
Postconditions:

POST-1. The user's Coin balance is increased and a transaction log is recorded.
Normal Flow:

A. Payment Successfully Processed

  1. Actor selects a Coin package (e.g., 100,000 VND for 10,000 Coins).
  2. The system creates a "PENDING" transaction record in the database with a unique transaction reference (TxnRef).
  3. The system generates a secure VNPay payment URL, signing the parameters using HMAC-SHA512 and the HashSecret.
  4. The system redirects the actor to the VNPay Sandbox payment gateway.
  5. Actor inputs test card details (NCB bank) on the VNPay gateway and completes the payment.
  6. VNPay redirects the actor back to the application's return URL.
  7. Simultaneously, VNPay sends an asynchronous server-to-server IPN (Instant Payment Notification) request to the application.
  8. The system receives the IPN request and verifies the HMAC-SHA512 signature.
  9. The system verifies the TxnRef exists and is in "PENDING" state.
  10. The system checks the VNPay response code indicating success (e.g., "00").
  11. The system initiates a database transaction with a pessimistic write lock on the user's wallet.
  12. The system adds the purchased Coins to the wallet balance.
  13. The system updates the transaction record status to "SUCCESS".
  14. The system commits the database transaction and responds with HTTP 200 OK to VNPay.
  15. The actor sees a "Payment Successful" confirmation page on the frontend.
Alternative Flows:

A.10 Alt Payment Failed or Cancelled

  1. The system receives an IPN request with a failure response code (e.g., insufficient funds on test card, or user clicked cancel).
  2. The system updates the transaction record status to "FAILED" or "CANCELLED".
  3. The system responds with HTTP 200 OK to VNPay (acknowledging receipt).
  4. The actor sees a "Payment Failed" page.
Exceptions:

EX-8 Invalid IPN Signature

  1. The system determines the HMAC signature attached to the IPN request does not match the computed signature.
  2. The system rejects the request (potential spoofing).
  3. The system logs the security incident.
  4. The system responds to VNPay with the "Invalid Checksum" error code.

EX-9 Duplicate IPN Request

  1. The system determines the TxnRef is already marked as "SUCCESS".
  2. The system ignores the duplicate request and responds to VNPay with the "Order already confirmed" error code to stop further retries.
Priority: Critical, Must Have
Frequency of Use: Medium
Business Rules:
  • All payment confirmations MUST rely solely on the backend IPN webhook from VNPay, never on the frontend return URL, to prevent client-side manipulation.
  • A pessimistic lock MUST be used when updating the wallet balance during the IPN processing to prevent concurrency issues if VNPay sends simultaneous duplicate IPN requests.
Other Information: None
Assumptions:
  • Actor has a stable internet connection.
