UC ID and Name: UC-04 Login with Google
Created By: Nguyễn Ngọc Date Created: 2026-09-19
Primary Actor: Guest Secondary Actors: Google OAuth2 Server
Trigger: Actor clicks the "Continue with Google" button on the login/registration page.
Description: Allows a user to log in or automatically create a new active account using their Google credentials via the OAuth2 protocol.
Preconditions:

PRE-1. The actor is not currently authenticated.

PRE-2. The application is properly registered with Google Cloud Console and possesses a valid Client ID and Secret.
Postconditions:

POST-1. A secure session is created and the actor is authenticated.
Normal Flow:

A. Login via OAuth2 Successfully

  1. Actor clicks the "Continue with Google" button.
  2. The system redirects the actor to the Google OAuth2 consent screen.
  3. Actor authenticates with Google and grants the necessary permissions (email, profile).
  4. Google redirects the actor back to the application's callback URL with an authorization code.
  5. The system exchanges the authorization code for an access token via Google API.
  6. The system retrieves the user's email and basic profile information using the access token.
  7. The system checks if a user record with this email already exists in the database.
  8. The system determines the user exists and their status is ACTIVE.
  9. The system initializes a secure session for the user.
  10. The system redirects the user to the homepage.
Alternative Flows:

A.7 Alt Create New Account (SSO Registration)

  1. The system determines no user record exists for the provided Google email.
  2. The system automatically creates a new user record.
  3. The system sets the USER_STATUS directly to ACTIVE (bypassing email verification since Google already verified it).
  4. The system generates a random secure password for the user (or leaves the password field empty/null if only SSO is allowed).
  5. The system initializes the session.
  6. Back to step 10.

A.8 Alt Banned Account

  1. The system determines the user's status is BANNED.
  2. The system rejects the login attempt.
  3. The system displays an error message indicating the account is suspended.
  4. The system redirects the user to the login page.
Exceptions:

EX-3 OAuth2 Consent Denied

  1. The actor denies consent on the Google authorization screen.
  2. Google redirects back to the application with an access_denied error.
  3. The system displays a "Login cancelled" message.

EX-5 API Timeout/Failure

  1. The system fails to communicate with Google's API to exchange the token or fetch profile data.
  2. The system displays a generic "Third-party authentication failed, please try again" message.
Priority: High, Must Have
Frequency of Use: High
Business Rules:
  • Accounts created via Google OAuth2 do not require a separate email verification step.
Other Information: None
Assumptions:
  • Actor has an active Google account.
