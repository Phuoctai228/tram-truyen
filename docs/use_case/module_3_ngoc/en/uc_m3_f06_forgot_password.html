Functional Description Template

UC ID and Name: UC-06 Forgot Password
Created By: Nguyễn Ngọc Date Created: 2026-09-19
Primary Actor: Guest Secondary Actors: None
Trigger: Actor clicks the "Forgot Password?" link on the login page.
Description: Allows a user who has lost their password to recover access to their account by receiving a secure, time-sensitive reset token via email.
Preconditions:

PRE-1. The actor is not logged in.

PRE-2. The system's email service is operational.
Postconditions:

POST-1. The user's password is successfully updated in the database.
Normal Flow:

A. Reset Password Successfully

  1. Actor clicks "Forgot Password?".
  2. The system renders a form requesting the registered email address.
  3. Actor enters their email and submits.
  4. The system verifies the email exists and the account is ACTIVE.
  5. The system generates a unique, cryptographically secure reset token with a 15-minute expiration.
  6. The system saves the hashed token to the database.
  7. The system sends an email containing a password reset link (with the raw token) to the actor.
  8. The system displays a confirmation message: "Check your email."
  9. Actor clicks the link in their email.
  10. The system validates the token.
  11. The system renders the "New Password" form.
  12. Actor enters and confirms their new password.
  13. The system hashes the new password with BCrypt and updates the user record.
  14. The system invalidates the reset token.
  15. The system displays a success message and redirects to the login page.
Alternative Flows:

A.4 Alt Non-existent Email

  1. The system determines the email does not exist in the database.
  2. To prevent enumeration attacks, the system proceeds exactly as if the email exists (jumping to step 8) but does not actually generate or send any email.

A.10 Alt Invalid or Expired Token

  1. The system determines the token from the link is invalid, already used, or expired.
  2. The system displays an error message: "The reset link is invalid or has expired."
  3. The system provides a button to request a new link (Back to step 1).
Exceptions:

None
Priority: High, Must Have
Frequency of Use: Medium
Business Rules:
  • Reset tokens must be strictly single-use and expire within 15 minutes.
  • The system must never reveal whether an email address is registered or not during the recovery process.
Other Information: None
Assumptions:
  • Actor has access to their email account.
