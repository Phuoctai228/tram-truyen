UC ID and Name: UC-07 Change Password
Created By: Nguyễn Ngọc Date Created: 2026-09-19
Primary Actor: Member, Staff, Admin Secondary Actors: None
Trigger: Actor clicks the "Change Password" button in their account settings page.
Description: Allows an authenticated user to update their account password by providing their current password and a new, strong password.
Preconditions:

PRE-1. The actor is currently authenticated.

PRE-2. The actor's account was not created exclusively via Google OAuth2 (must have a local password).
Postconditions:

POST-1. The user's password is successfully updated in the database.
Normal Flow:

A. Change Password Successfully

  1. Actor accesses the Account Settings page and selects "Change Password".
  2. The system renders a form requesting Current Password, New Password, and Confirm New Password.
  3. Actor inputs the data and submits the form.
  4. The system validates that the New Password and Confirm New Password match and meet the strength criteria.
  5. The system retrieves the user's current hashed password from the database.
  6. The system verifies the provided Current Password matches the hash.
  7. The system hashes the New Password using BCrypt.
  8. The system updates the user record in the database with the new hash.
  9. The system clears any other active sessions for this user (forcing re-login on other devices).
  10. The system displays a success notification and keeps the current session active.
Alternative Flows:

A.4 Alt Weak or Mismatched Password

  1. The system determines the new password does not meet the policy or does not match the confirmation.
  2. The system displays specific validation errors.
  3. Back to step 3.

A.6 Alt Incorrect Current Password

  1. The system determines the provided current password does not match the stored hash.
  2. The system displays an error message: "Incorrect current password."
  3. Back to step 3.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system determines the actor is not logged in.
  2. The system redirects the user to the login page.
Priority: High, Must Have
Frequency of Use: Low
Business Rules:
  • Accounts registered solely via OAuth2 without a local password cannot change their password through this interface. The system must display a message indicating they log in via a third party.
Other Information: None
Assumptions:
  • None
