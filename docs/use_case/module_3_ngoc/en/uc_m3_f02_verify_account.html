Functional Description Template

UC ID and Name: UC-02 Verify Account
Created By: Nguyễn Ngọc Date Created: 2026-09-19
Primary Actor: Guest Secondary Actors: None
Trigger: Actor submits the 6-digit OTP code on the Account Verification page.
Description: Completes the registration process by validating an OTP sent to the actor's email. Upon success, the account is activated.
Preconditions:

PRE-1. The actor must have an account with a PENDING_VERIFICATION status.

PRE-2. A valid OTP must have been generated and sent to the actor's email.
Postconditions:

POST-1. The actor's account status is updated to ACTIVE.
Normal Flow:

A. Verify Account Successfully

  1. Actor enters the 6-digit OTP and submits the verification form.
  2. The system retrieves the pending user record associated with the current session/email.
  3. The system validates the submitted OTP against the stored OTP in the database/cache.
  4. The system verifies that the OTP has not expired.
  5. The system updates the user's USER_STATUS to ACTIVE.
  6. The system securely destroys the used OTP record.
  7. The system displays a success message indicating the account is ready to use.
  8. The system redirects the actor to the Login page.
Alternative Flows:

A.3 Alt Invalid OTP

  1. The system determines the submitted OTP does not match the stored OTP.
  2. The system displays an error message: "Invalid verification code."
  3. Back to step 1.

A.4 Alt Expired OTP

  1. The system determines the OTP time-to-live (TTL) has expired.
  2. The system securely destroys the expired OTP record.
  3. The system displays an error message instructing the actor to request a new code.
  4. Back to step 1.

A.4 Alt Request New OTP

  1. Actor clicks the "Resend Code" button on the verification page.
  2. The system generates a new OTP and updates the cache/database.
  3. The system triggers an async task to send the new OTP via email.
  4. The system displays a confirmation message.
  5. Back to step 1.
Exceptions:

EX-2 User Not Found or Active

  1. The system determines the associated user record does not exist or is already ACTIVE.
  2. The system interrupts the flow.
  3. The system redirects the actor to the homepage with a generic message.
Priority: Critical, Must Have
Frequency of Use: High
Business Rules:
  • The OTP must be strictly 6 digits and valid for a limited time window (e.g., 5 minutes).
  • The OTP sending mechanism must have rate-limiting (e.g., 1 request per minute) to prevent email spam.
Other Information: None
Assumptions:
  • Actor has access to their email inbox and a stable internet connection.
