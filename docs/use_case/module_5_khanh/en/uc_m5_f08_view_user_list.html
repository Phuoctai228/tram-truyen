UC ID and Name: UC-08 View User List
Created By: KhanhND Date Created: 2026-09-23
Primary Actor: Admin Secondary Actors: None
Trigger: Admin clicks "User Management" menu item in the admin navigation panel.
Description: Provides an administrative dashboard to browse all registered user accounts, search by email or name, filter by assigned roles (ROLE_MEMBER, ROLE_STAFF, ROLE_ADMIN) or account status (ACTIVE, BANNED, PENDING_VERIFICATION), and inspect wallet Coin balances.
Preconditions:

PRE-1. The user is authenticated with the Admin role.
Postconditions:

POST-1. Admin views the paginated user accounts table with filtering and management controls.
Normal Flow:

A. View User List Successfully

  1. Admin navigates to the user management page.
  2. The system verifies the actor's Admin authorization.
  3. The system queries user accounts from the database with default pagination.
  4. The system calculates total user count and pagination metadata.
  5. The system renders the user accounts table (ID, Full Name, Email, Role, Coin Balance, Account Status, Registered Date) and action buttons ( "Details" , "Change Role" , "Ban/Enable" ).
  6. Admin inputs search keywords (email or name) or selects role/status dropdown filters.
  7. Admin clicks "Search" button.
  8. The system queries user records meeting the specified filter criteria.
  9. The system updates the table rendering the filtered user list.
Alternative Flows:

A.5 View User Details

  1. Admin clicks "Details" button on a specific user row.
  2. The system queries extended user telemetry (login logs, total deposits, unlocked chapter count).
  3. The system renders a user profile overview modal.
  4. Admin inspects details and clicks "Close" button.
  5. Back to step 5.

A.8 No Users Found

  1. The system identifies no user records matching the filter parameters.
  2. The system displays a no results found notification.
  3. Back to step 6.

A.5 Change Page

  1. Admin clicks a page number or "Next" , "Previous" button on pagination controls.
  2. The system queries the requested page records.
  3. The system updates the user accounts table.
  4. Back to step 5.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system displays an authentication error message.
  2. The system redirects the user to the login page.

EX-2 Access Denied

  1. The system determines the user lacks Admin privileges.
  2. The system renders a 403 Forbidden page.
Priority: High, Must Have
Frequency of Use: High (Daily)
Business Rules: BR-04
Other Information: Default pagination limit is 20 users per page.
Assumptions:
  • Admin has a stable internet connection.
