Functional Description Template

UC ID and Name: UC-03 Resolve Reports
Created By: KhanhND Date Created: 2026-09-23
Primary Actor: Staff, Admin Secondary Actors: None
Trigger: Actor accesses "Report Management" from the administrative navigation sidebar.
Description: Provides a centralized management dashboard for Staff and Admin to review reported tickets (comment reports, novel/chapter content reports), inspect violation context, execute resolution decisions (Approve with sanctions or Reject report), record audit logs, and automatically notify the reporter.
Preconditions:

PRE-1. The actor is authenticated with Staff or Admin role.
Postconditions:

POST-1. Report ticket status is transitioned to 'PROCESSED' or 'REJECTED'.

POST-2. Resolution timestamp, processor ID, and administrative decision note are logged in the database.

POST-3. Appropriate sanctions are applied to the violating entity (comment hidden, chapter locked, novel archived) if approved.

POST-4. A notification containing resolution details is automatically sent to the reporter's mailbox.
Normal Flow:

A. Resolve Report Successfully

  1. Actor accesses the report management page.
  2. The system verifies the actor's administrative authorization.
  3. The system retrieves the list of reports from the database with pending status.
  4. The system renders the report table organized by categorized tabs, with filter and pagination controls.
  5. Actor selects a specific report record and clicks "View Details" button.
  6. The system retrieves the detailed report ticket and the context of the reported entity.
  7. The system displays the report resolution modal with entity preview and action buttons ( "Take Action" , "Reject Report" ).
  8. Actor clicks "Take Action" button, enters resolution note, and selects the disciplinary sanction.
  9. Actor clicks "Confirm" button.
  10. The system validates the resolution note is not empty.
  11. The system executes a database transaction updating report status to 'PROCESSED', saving processor ID and resolution timestamp.
  12. The system updates the reported entity's status corresponding to the chosen disciplinary sanction.
  13. The system generates a notification dispatching the result to the reporting Member's mailbox.
  14. The system closes the modal and displays a report resolved successfully notification.
Alternative Flows:

A.8 Reject Report

  1. Actor clicks "Reject Report" button, enters rejection reason, and clicks "Confirm" button.
  2. The system validates rejection explanation is provided.
  3. The system updates report status to 'REJECTED', recording processor ID and resolution timestamp.
  4. The system sends an explanatory notification to the reporter's mailbox.
  5. The system closes the modal and displays a rejection completed message.
  6. Back to step 4.

A.4 Switch Tab or Apply Filters

  1. Actor clicks another tab (Comment Reports / Content Reports) or changes status filter.
  2. The system retrieves report records matching the updated criteria.
  3. The system refreshes the displayed table.
  4. Back to step 4.

A.10 Empty Resolution Note

  1. The system determines the resolution note field is blank.
  2. The system displays a validation error requiring mandatory explanation.
  3. Back to step 8.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system displays an authentication error message.
  2. The system redirects the user to the login page.

EX-2 Access Denied

  1. The system determines the actor lacks Staff or Admin privileges.
  2. The system renders a 403 Forbidden error page.
Priority: High, Must Have
Frequency of Use: High (Daily)
Business Rules: BR-05
Other Information: Adheres strictly to mandatory audit logging and sender notification requirements.
Assumptions:
  • Actor has a stable internet connection.
