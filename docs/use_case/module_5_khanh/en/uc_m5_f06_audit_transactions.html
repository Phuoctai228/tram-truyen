Functional Description Template

UC ID and Name: UC-06 Audit Transactions
Created By: KhanhND Date Created: 2026-09-23
Primary Actor: Admin Secondary Actors: None
Trigger: Admin selects "Audit Transactions" under the financial management section.
Description: Empowers Admin to inspect, reconcile, and audit the complete ledger of Coin balance movements across the entire platform (deposit orders via VNPay sandbox and Coin deductions for VIP chapter unlocks), matching external bank transaction IDs with IPN webhook logs to ensure financial integrity.
Preconditions:

PRE-1. The user is authenticated with the Admin role.
Postconditions:

POST-1. Admin views financial summary metrics and paginated transaction audit records.
Normal Flow:

A. Audit Transactions Successfully

  1. Admin navigates to the transaction audit page.
  2. The system verifies the actor's Admin authorization.
  3. The system calculates high-level financial metrics (total VNĐ deposited, total Coin issued, and total Coin consumed).
  4. The system queries deposit orders and transaction ledger records applying default pagination.
  5. The system renders summary metric cards and the audit data table (Order Code, User, Type, Amount/Coin, Status, Bank Transaction Code, Timestamp).
  6. Admin inputs search criteria or selects filter parameters (date range, transaction type, order code, user email).
  7. Admin clicks "Search" button.
  8. The system queries database records satisfying the filter criteria.
  9. The system updates the audit table with paginated filtered results.
Alternative Flows:

A.5 View Raw IPN Log

  1. Admin clicks "View IPN Log" button on a specific VNPay deposit record.
  2. The system queries matching raw payload records from the payment_logs table by order code.
  3. The system displays a modal containing raw JSON response, gateway IP address, and verification status.
  4. Admin inspects audit details and clicks "Close" button.
  5. Back to step 5.

A.8 No Matching Transactions

  1. The system determines no records match the specified search filters.
  2. The system renders an empty results notification.
  3. Back to step 6.

A.9 Change Page

  1. Admin clicks a page number or "Next" , "Previous" button on pagination controls.
  2. The system calculates page offset and retrieves the requested records.
  3. The system refreshes the transaction audit table.
  4. Back to step 9.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system displays an authentication error message.
  2. The system redirects the user to the login page.

EX-2 Access Denied

  1. The system determines the user lacks Admin privileges.
  2. The system displays a 403 Forbidden page.
Priority: High, Must Have
Frequency of Use: Periodic (Daily / Weekly)
Business Rules: BR-01, BR-03
Other Information: Cash refunds or balance withdrawals are strictly unsupported per platform rules.
Assumptions:
  • Admin has a stable internet connection.
