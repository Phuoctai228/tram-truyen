UC ID and Name: UC-09 Manage Staffs
Created By: Khánh Date Created: 2026-09-23
Primary Actor: Admin Secondary Actors: None
Trigger: Admin clicks `"Change Role"` button on a user record within the user management view.
Description: Enables Admin to assign or revoke editorial and moderation responsibilities by granting ROLE_STAFF or ROLE_ADMIN to accounts, enforcing security constraints to prevent accidental self-demotion, and recording an administrative audit log.
Preconditions:

PRE-1. The user is authenticated with the Admin role.

PRE-2. Target user account exists and is in an ACTIVE status.
Postconditions:

POST-1. Target user role mappings are updated in the user_roles table.

POST-2. System audit log documents the role change action performed by the Admin.

POST-3. A notification informing of the role change is dispatched to the target user's mailbox.
Normal Flow:

A. Manage Staffs Successfully

  1. Admin clicks `"Change Role"` button on a specific user record.
  2. The system retrieves the current actor's session data.
  3. The system queries the target user's assigned roles and all system roles.
  4. The system renders the role management modal with user identity and role choices (ROLE_MEMBER, ROLE_STAFF, ROLE_ADMIN).
  5. Admin selects the new role configuration to be assigned.
  6. Admin clicks `"Save Changes"` button.
  7. The system evaluates security constraints ensuring the Admin does not revoke their own ROLE_ADMIN privilege.
  8. The system displays a confirmation dialog summarizing the role modification.
  9. Admin clicks `"Confirm"` button.
  10. The system executes a database transaction updating role mappings in user_roles table.
  11. The system records an administrative audit log capturing role transition details.
  12. The system dispatches a role update notification to the target user's mailbox.
  13. The system closes the modal and displays a role updated successfully confirmation message.
Alternative Flows:

A.7 Self-Demotion Attempt

  1. The system detects the target user is the currently logged-in Admin and ROLE_ADMIN was deselected.
  2. The system displays a warning message that an administrator cannot revoke their own administrator role.
  3. Back to step 4.

A.9 Cancel Confirmation

  1. Admin clicks `"Cancel"` button on the confirmation dialog.
  2. The system aborts the operation and closes the dialog.
  3. Back to step 4.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system displays an authentication error message.
  2. The system redirects the user to the login page.

EX-2 Access Denied

  1. The system determines the user lacks Admin privileges.
  2. The system displays a 403 Forbidden page.

EX-3 Target Account Unavailable

  1. The system determines the target user record no longer exists or is currently banned.
  2. The system displays an error message indicating invalid target account.
Priority: Medium, Should Have
