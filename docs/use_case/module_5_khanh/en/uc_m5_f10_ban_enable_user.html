Functional Description Template

UC ID and Name: UC-10 Ban/Enable User
Created By: Khánh Date Created: 2026-09-23
Primary Actor: Admin Secondary Actors: None
Trigger: Admin clicks `"Ban User"` or `"Enable User"` button on a specific account record in the user table.
Description: Enables Admin to suspend platform access for users violating community standards (updating status to BANNED), automatically calculating progressive ban durations and invalidating active sessions; or manually restore access (status to ACTIVE) prior to ban expiry.
Preconditions:

PRE-1. The user is authenticated with the Admin role.

PRE-2. Target user account exists in the database.
Postconditions:

POST-1. Target user account status is updated to BANNED or ACTIVE.

POST-2. If banned, all active user sessions are terminated immediately.

POST-3. An administrative audit log entry is recorded with rationale and ban expiry timestamp.
Normal Flow:

A. Ban User Successfully

  1. Admin clicks `"Ban User"` button on an offending user record.
  2. The system retrieves the current actor's session data.
  3. The system evaluates safety constraints ensuring Admin cannot ban their own account.
  4. The system queries previous violation history and ban counts for the target account.
  5. The system calculates progressive ban duration according to business rules (1st: 24h, subsequent: double previous, up to 1 year max).
  6. The system renders the ban confirmation modal with calculated duration and mandatory reason textarea.
  7. Admin reviews the duration, enters detailed violation reasons, and clicks `"Confirm Ban"` button.
  8. The system validates the violation reason field is not empty.
  9. The system executes a database update setting status to BANNED and recording ban expiry timestamp.
  10. The system revokes all active session tokens associated with the banned account.
  11. The system creates an audit log entry detailing the ban reason and duration.
  12. The system closes the modal and displays an account banned successfully message.
Alternative Flows:

A.1 Enable User Before Expiry

  1. Admin clicks `"Enable User"` button on an account currently marked as BANNED.
  2. The system displays an unban confirmation modal with an unban rationale input.
  3. Admin enters justification and clicks `"Confirm Enable"` button.
  4. The system updates user status to ACTIVE and clears remaining ban duration.
  5. The system logs the early unban administrative action.
  6. The system dispatches an account reactivated notification to the user's mailbox.
  7. The system refreshes the UI and displays an account restored successfully message.

A.3 Self-Ban Attempt

  1. The system detects the target user is identical to the currently authenticated Admin.
  2. The system displays a warning message that you cannot ban your own account.
  3. The ban operation is aborted.

A.8 Blank Ban Rationale

  1. The system detects the reason textarea is blank.
  2. The system displays a validation error requiring explicit justification.
  3. Back to step 7.
Exceptions:

EX-1 Session Invalid (Not Logged In)

  1. The system displays an authentication error message.
  2. The system redirects the user to the login page.

EX-2 Access Denied

  1. The system determines the user lacks Admin privileges.
  2. The system renders a 403 Forbidden page.

EX-3 Target Account Not Found

  1. The system determines the target record is missing from the database.
  2. The system displays an error message and refreshes the user table.
Priority: High, Must Have
Frequency of Use: Medium (When severe violations occur)
Business Rules: BR-04
Other Information: Implements progressive penalty scaling and permits discretionary manual early restoration by Admin.
Assumptions:
  • Admin has a stable internet connection.
