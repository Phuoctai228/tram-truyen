II. Installation Guides

Detailed Guide to Installing PostgreSQL on Windows

Step 1: Download the PostgreSQL installer

Download the PostgreSQL installer suitable for your Windows operating system from the official PostgreSQL website: https://www.enterprisedb.com/downloads/postgres-postgresql-downloads.

Below, I select the latest installer for Windows x86-64.

Step 2: Open the .exe file

After downloading PostgreSQL, open the downloaded .exe file and click Next on the setup welcome screen.

Step 3: Update the location

  • Change the installation directory if needed, otherwise leave it as default.
  • Click Next.

Step 4: Select components

  • You can select the components you want to install on your system.
  • Click the Next button to continue.

Step 5: Check the data directory

  • You can change the location where data is stored.
  • Click the Next button to continue.

Step 6: Enter password

  • Enter a password and make sure to take note of it.
  • Click Next.

Step 7: Check port options

  • Keep the default port or enter the port of your choice.
  • Click Next.

Step 8: Review pre-installation summary

  • Review the summary before proceeding with the installation.
  • Click Next.

Step 9: Ready to install

Click the Next button.

Step 10: Check Stack Builder prompt

  • Once the installation is complete, you will see the Stack Builder prompt.
  • Check the Stack Builder box if you wish to use it. Click the Finish button to complete.

Step 11: Launch PostgreSQL

To launch PostgreSQL, go to the Start Menu and search for pgAdmin 4.

Step 12: Locate PostgreSQL 16

Click on Servers > PostgreSQL 16 in the left sidebar.

Step 13: Enter password

Enter the superuser password configured during the installation process. Click OK to continue.

Thus, we have successfully installed PostgreSQL on Windows and are ready to use it.

III. User Manual

This section provides an overall description of the application, summaries of the core system workflows, and exhaustive step-by-step user guides for the primary application workflows (Member, Staff, and Administrator).

1. Overview

1.1. Application Description

Online Novels System (Tràm Truyển) is a modern digital web-novel reading and publishing platform built with Spring Boot and Thymeleaf. The platform bridges authors, translators, and passionate readers by delivering high-quality web novels with rich user experience features: customizable reader views (themes, typography, font size), automated Text-to-Speech (TTS) audio narration, continuous reading progress synchronization across devices, gamified daily check-in streaks, and a secure coin-based microtransaction system for unlocking premium chapters.

1.2. Application Workflows Summary

The system accommodates four key user roles: Guest, Member (Reader), Staff (Content Moderator/Uploader), and Admin (System Administrator). The primary application workflows include:

  • 1. Member Discovery, Reading and Chapter Unlocking Workflow: The central reader journey starting from account registration and login, daily check-in reward collection, multi-criteria novel search and filtering, personal bookshelf curation, free/audio chapter reading, coin-based VIP chapter purchases, and online wallet top-ups via VNPay and MoMo.
  • 2. Member Community & Feedback Workflow: Reader participation through 1-to-5 star novel reviews (strictly limited to one review per novel to prevent vote inflation), chapter comments, and reporting offensive content or textual errors to moderators.
  • 3. Staff Content Publishing & Moderation Workflow: Allows staff members to draft, edit, publish, and schedule novels and chapters, perform soft deletion to preserve user reading data, and resolve reader complaints or violation reports.
  • 4. Admin System & Financial Audit Workflow: Empowers administrators to manage staff permissions, adjust coin exchange rates, audit financial logs and coin transactions, and execute progressive account suspensions.

2. Member Reading and Chapter Unlocking Workflow

2.1. Purpose & Preconditions

  • Target Actor: Guest (Visitor) transitioning to Member (Registered Reader).
  • Preconditions: Visitor accesses the website using a standard web browser on a desktop or mobile device.
  • Purpose: Walk through the complete reader experience, beginning with creating an account and logging in, claiming free daily check-in coins, discovering stories through search and filters, reading free chapters with personalized reader themes, unlocking VIP chapters with coins, topping up wallet balance via online payment methods, and participating in the reader community.

3. Staff Content Publishing, Scheduling, and Moderation Workflow

3.1. Purpose & Preconditions

  • Target Actor: Content Moderator & Uploader (Staff).
  • Preconditions: Staff member logs in with assigned editorial credentials to access the content management workspace.
  • Purpose: Provide content staff and editors with an intuitive, operational manual to create and organize novels, compose and sequence chapters, configure VIP coin prices or free reading access, schedule releases, preserve reading histories via soft archiving, and resolve reader-submitted moderation reports.

3.2. Workflow Activity Diagram

Figure III-11: Staff Content Publishing, Scheduling, and Moderation Flowchart

3.3. Detailed Step-by-Step Guide

Step 1: Staff Dashboard & Content Workspace Overview

Upon logging into the Staff portal, the user accesses the Staff Content Dashboard. The workspace provides quick navigation cards and metrics summarizing the novels under management, chapters pending review or published, and incoming user moderation tickets, allowing editors to prioritize daily editorial assignments.

[Screenshot Placeholder: Staff Content Management Dashboard (Figure III-12)]
Displaying active novel counts, recent publishing activity, and moderation queues.

Step 2: Novel Creation, Metadata & Genre Mapping

From the story management screen, staff members can introduce new titles by clicking the creation button. The editor enters comprehensive story metadata including title, author name, synopsis, publishing status (Ongoing or Completed), and uploads the promotional cover image. Staff assign appropriate genre categories to ensure the novel appears correctly in public category catalogs and search filters.

[Screenshot Placeholder: Story Metadata Editor and Cover Upload Modal (Figure III-13)]
Displaying title, author, synopsis inputs, category checkboxes, and cover image preview.

Step 3: Chapter Composition, Drafting & Auto-Numbering

Selecting a novel brings staff to its dedicated chapter directory. When creating a new chapter, the system automatically detects existing chapters and pre-fills the next sequential chapter number to prevent duplicate or conflicting indexes. Staff enter the chapter title and compose the story text in the chapter editor, with options to either save the work as a draft for ongoing revisions or publish it immediately.

[Screenshot Placeholder: Chapter Editor and Auto-Numbering Interface (Figure III-14)]
Displaying chapter sequence counter, title field, rich text content area, and draft/publish buttons.

Step 4: VIP Monetization & Chapter Pricing Configuration

During chapter creation or revision, staff configure the accessibility tier for readers. Leaving the coin price at zero marks the chapter as free for all readers. Setting a positive coin value automatically designates the chapter as premium VIP content, requiring readers to unlock it with wallet coins. This monetization setting seamlessly integrates into reader reading sessions.

[Screenshot Placeholder: VIP Chapter Coin Pricing Configuration (Figure III-15)]
Displaying coin price input, free versus VIP indicators, and pricing validation rules.

Step 5: Story Archiving & Soft-Deletion Preservation

When a novel concludes or must be withdrawn from active circulation, staff can safely archive or soft-delete the story. Rather than permanently removing database records, the system marks the novel as archived. This keeps it hidden from public exploration listings while safely preserving existing readers' reading histories, unlocked chapters, and bookshelf bookmarks.

[Screenshot Placeholder: Story Archiving and Soft-Deletion Confirmation (Figure III-16)]
Displaying archive status switch, soft deletion confirmation dialog, and integrity notice.

Step 6: Reader Report Investigation & Content Resolution

In the incident moderation center, staff review user reports submitted by readers regarding abusive comments or corrupted chapter text. Staff inspect the flagged excerpt, evaluate community guideline compliance, and record an approved or rejected decision with explanatory rationale. Closing the report updates the moderation ticket and keeps community discussions constructive and clean.

[Screenshot Placeholder: Incident Report Review and Moderation Resolution Panel (Figure III-17)]
Displaying report list tabs (Comments, Chapter Content), reporter details, and resolution note inputs.

4. Administrator Governance, Audit, and User Management Workflow

4.1. Purpose & Preconditions

  • Target Actor: System Administrator.
  • Preconditions: Administrator logs in with administrative credentials to access management capabilities.
  • Purpose: Provide platform administrators with an easy-to-follow operational guide to monitor real-time platform health, configure coin exchange rates, audit financial transaction histories, maintain novel categories, manage user accounts and suspensions, and resolve reader dispute reports.

4.2. Workflow Activity Diagram

Figure III-18: Administrator Operational Governance and Audit Decision Flowchart

4.3. Detailed Step-by-Step Guide

Step 1: Admin Dashboard & System Metric Monitoring

Upon logging in with administrator credentials, the user enters the central Admin Dashboard. The overview screen features dynamic metric cards displaying daily gross revenue, total registered members, pending moderation reports, and recent system transaction volume, providing an immediate snapshot of the platform's operational health.

[Screenshot Placeholder: Administrator Overview Dashboard (Figure III-19)]
Displaying revenue analytics, user counts, and pending task indicators.

Step 2: System Configuration & Coin Exchange Rate Management

From the side navigation menu, the administrator selects the System Configuration section to set economic parameters. The administrator adjusts the conversion rate between cash (VND) and Coins, and configures bonus coin incentives for promotional top-up packages. Saving these adjustments immediately updates the pricing across all reader top-up packages on the live website.

[Screenshot Placeholder: System Configuration and Coin Pricing (Figure III-20)]
Displaying exchange rate sliders, bonus coin multipliers, and save confirmation.

Step 3: Financial & Transaction Audit Logging

Within the financial management section, the administrator monitors payment gateway reconciliations and member coin histories. The audit interface allows filtering by date range, transaction status (Successful, Pending, Failed), or username. This helps administrators verify that balances remain accurate and promptly investigate any payment inquiries or coin discrepancies reported by readers.

[Screenshot Placeholder: Transaction & Financial Audit Log (Figure III-21)]
Displaying audit tables, payment gateway transaction IDs, and coin ledger entries.

Step 4: Category Management & Deletion Safeguard

Navigating to the Category Management screen, the administrator maintains the platform's genre taxonomy by adding new categories or updating existing names and descriptions. If an administrator attempts to remove a category that currently has active novels assigned to it, the system displays a safeguard warning and prevents deletion to protect story data from being orphaned.

[Screenshot Placeholder: Category Management and Deletion Safeguard (Figure III-22)]
Displaying category list, add modal, and dependency violation warning alert.

Step 5: User Disciplinary Actions & Progressive Account Ban

From the User Management page, the administrator searches reader accounts, reviews profile details, and manages permissions. When addressing community rule violations, the administrator can apply temporary or extended suspensions—ranging from a 24-hour initial penalty to longer terms for repeat offenses. Administrators can also lift suspensions early if a user appeal is approved.

[Screenshot Placeholder: User Directory and Ban/Enable Modal (Figure III-23)]

Step 6: Dispute Report Resolution & Broadcast Notifications

In the moderation center, the administrator handles user reports concerning abusive comments or corrupted story content. The administrator reviews the flagged item, records the resolution decision with explanatory notes, and resolves the ticket. The administrator can then use the notification sender to send direct updates to the reporter or publish general announcements to all members.
